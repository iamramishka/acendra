## Implementation and design comparison

Cards and FilledButton actions open /learn/:courseId, which the existing router
maps to CourseOverviewScreen. Home's separate lesson-resume behavior is unchanged.
Progress repository failures now reach AsyncError rather than being swallowed as
an empty success. Automatic retries are disabled for this provider so failures
remain visible until the student selects Retry progress. This refreshes only the
summary. Public feedback includes loading, failure and missing-summary messages;
backend error text is never displayed.

During progress loading/failure or incomplete coverage, filters cannot reliably
classify every enrollment, so the full enrolled library stays accessible. Known
per-course summaries remain visible when a successful response is partial. On
complete recovery, filters and counts/percentages return. A failed refresh does
not keep showing stale progress as current.

Recorded artifact layout in compare.md: My Courses / Your learning library,
All/In Progress/Not Started/Completed, large artwork/title/blurb cards, completed
lesson counts, percent/bar and Start/Continue actions, Explore empty state.
The screen now uses that subtitle, larger artwork and actual action buttons,
retaining the existing application shell and theme tokens. Review Course remains
the completed-course action. The enrollment contract has no category field;
category labels are not invented or added through an unrelated backend change.

Therefore no direct side-by-side artifact or authenticated deployed My Courses
comparison is claimed. Flutter-rendered previews use synthetic fixtures and are
