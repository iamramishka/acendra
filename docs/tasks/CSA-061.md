Migration 20261011000300 adds a guarded service-only role mutation RPC,
immutable audit events and an operator-only first-admin bootstrap. Browser clients
can read their own current eligible grants and safe role definitions only.
Every mutation checks the actor's current eligible Auth account and current
super_admin grant under a transaction lock. MFA aal2, a reason and UUID request
are required. Self changes are forbidden. Concurrent changes cannot remove the
last eligible active administrator through this API. Revocation preserves history.
Audit insert failure rolls back the role change. Clients cannot supply actor or AAL.

POST /functions/v1/admin-assign-user-role accepts exactly student_id (UUID),
role_code (student/content_manager/finance_admin/super_admin), action (grant/revoke),
reason (nonblank, at most 500 characters), request_id (UUID). The handler validates
the exact Bearer token with Auth, checks subject, session UUID and aal2, then invokes
the restricted RPC with backend credentials. Current roles are never taken from
metadata or JWT role claims. Responses contain data with status, operation_status,
replayed, grant_id, audit_id. Identical request replay returns the current status of
the original grant; it does not reapply a later-revoked grant. Changed payload with
the same actor/request UUID returns409. Authorization failures403, invalid body400,
unverified token401, missing target404; internal details remain private.

Flutter Web should use direct fetch with Authorization and Content-Type headers.
ACENDRA_ADMIN_ALLOWED_ORIGINS accepts comma-separated exact origins. The local
default is http://127.0.0.1:8080. Release operators must explicitly configure approved
HTTPS origins. Approved preflight returns204; unknown origins are denied. CORS is
an additional browser boundary; verified identity/current database roles enforce authority.
