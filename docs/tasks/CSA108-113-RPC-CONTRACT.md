# CSA108–113 bank RPC contract

Owner CODEX financial_finalization, issue81 comment6110955186, branch codex/feat/csa-108-113-bank-database; isolated managed worktree. Base34e6624 requires unmerged PR79 migration016. Root and receipt/review workers agreed exact args before implementation. All RPCs EXECUTE service_role only, empty search_path, no direct client ledger grants. Endpoints remain disabled until inspector/resources, official bank destination and operational gates are approved. No real bank data/configuration is seeded.

This bounded implementation extends the approved signed-capability API proposal with one raw-byte backend-controlled upload endpoint. It does not claim legacy create-bank-receipt-upload/finalize-bank-receipt signed routes are implemented. Raw bytes are inspected before reservation, stored without upsert, retrieved and reinspected before finalization. No client capabilities or arbitrary paths. Failed unsafe inspection before preparation reserves nothing; uncertain storage retries reuse the original exact reservation, never race-delete objects.

`csa108_prepare_receipt(p_actor uuid,p_session_id uuid,p_aal text,p_key text,p_order uuid,p_digest text,p_size bigint,p_mime text,p_extension text)` returns `{upload_id,receipt_asset_id,submission_id,object_path,bucket,replayed,finalized}`. Asset UUID equals upload UUID. Path `actor/order/submission/upload.ext` generated exclusively in SQL; bucket bank-receipts. SHA256 lowercase, size1..5242880, PNG/png JPEG/jpg|jpeg PDF/pdf combinations only. Current account/session and owned bank order checked. New reservation requires pending_payment and bound versioned bank instructions. Same actor/key/digest metadata retries original reservation; changed bytes or scope conflicts. Different key cannot replace active submission. This result containing a private path stays trusted Edge-only.

`csa109_finalize_receipt(p_actor uuid,p_session_id uuid,p_aal text,p_upload_id uuid,p_digest text,p_size bigint,p_mime text,p_inspection_reference text)` returns `{order_id,submission_id,status:"submitted",replayed}`. Trusted configured inspector policy/reference is an ASCII identifier1..128; not client input. Handler attests actual downloaded bytes digest/size/MIME, signature, parseability, no unsafe/encrypted content. SQL rechecks reserved metadata, current owner/session, private bucket and stored object at exact path, legal order/submission state. Transaction marks asset validated, receipt submitted, order pending_verification and audit. No settlement, grant or paid transition. Finalized metadata/history and stored bytes cannot be overwritten. Storage RESTRICTIVE client policy defeats broad future permissive policies; trusted service path is guarded by reservation triggers.

`csa112_review_bank_transfer(p_actor uuid,p_session_id uuid,p_aal text,p_key text,p_submission uuid,p_decision text,p_verified_credit jsonb,p_public_reason text,p_private_notes text)` returns `{replayed,submission_id,order_id,status,order_status}`. Decision approve/reject. Current eligible finance_admin OR super_admin plus matching current AAL2 session; own review denied regardless role, including retries. Permission check holds610061 role mutation lock to serialize revocation.

Approve exact credit shape: `{destination_account_id:UUID,bank_transaction_id:string,amount_minor:canonical positive decimal string,currency:"LKR",settled_at:finite timestamp,source:"bank_portal"|"bank_statement"|"authenticated_bank_feed",order_reference:string,bank_credit_confirmed:true}`. Confirmation is an authorized independent reviewer's recorded assertion from business-controlled bank evidence, never automatic technical bank verification or receipt proof. Stable credit ID scoped to bound logical destination must be reliable; no receipt digest/student identifier substitute. Exact immutable amount/currency/order reference/destination required, no partial/FX/tolerance. Private notes optional <=2000. Credit/evidence stored only private reviewer ledger. Rejection credit null, bounded student-safe reason required, separate private notes.

Lock order: finance610061 -> current account/session SHARE -> actor/operation/key -> scoped bank settlement identity -> order UPDATE -> submission UPDATE -> beneficiary/course advisory -> enrollment UPDATE. Receipt preparation account/session -> actor/key -> order; finalization account/session -> order -> submission -> reservation. Online fulfillment uses same order-before-beneficiary order. Immutable order payment method prevents client-switching online/bank methods.

Submitted -> under_review is audited inside final decision transaction; approved settlement/order/submission/lifetime source/projection/audit/outbox/idempotency commit together. Existing revoked enrollment projection remains revoked conservatively; recorded new source cannot override broader restriction. Rejection retains receipt/review evidence, restores still-payable order pending_payment, no grant, permits new submission with fresh key on same order. Identical replay returns original safe result; changed payload or opposing completed decision conflicts. Reliable credit cannot fund two orders.
