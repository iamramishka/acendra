## Requirements and acceptance

SRS NFR-REL-005/007, SECURITY sections 35.2–35.4 and THREAT-013/015,
TESTING section 44, MVP AC-22 require actual restoration of database records,
protected object bytes, authorization and deletion-ledger handling. Approved
RPO/RTO, provider configuration, backup access/encryption/retention, and a named
recovery owner remain dependencies. Candidate 24-hour RPO/4-hour RTO are not
approved thresholds and this exercise cannot accept them.

## Reproducible exercise

Run with Python 3 and PostgreSQL 17 binaries:

```powershell
python tool/csa200_recovery_test.py
python tool/csa200_recovery.py --postgres-bin 'C:/Program Files/PostgreSQL/17/bin'
```

The harness creates a new temporary PostgreSQL cluster, binds only 127.0.0.1
on reserved port 61000, scrubs libpq environment overrides, and creates three new
databases. It accepts no existing database or connection URL. It never resets
an existing cluster. It stops its own cluster and deletes its synthetic scratch
directory on normal completion/error. An externally interrupted process may
require stopping that exact temporary cluster; never stop unrelated clusters.

It installs minimal synthetic Auth/Storage SQL shims and all sorted repository
migrations, runs the existing CSA-096 financial integrity suite with the final
rollback changed to commit **only in the disposable source**. The CSA-121/126
financial recovery and CSA-133 progress suites likewise commit disposable
fixtures, including actual audit/progress rows. It dumps with
`pg_dump -Fc`. It restores into the empty destination using `pg_restore
--exit-on-error`, compares every application/Auth/Storage table's complete row
digest and count, compares schema dumps including grants/RLS/constraints, and
reruns the profile isolation suite against the restored database. Schema comparison
independently reparses source DDL into a third empty database because PostgreSQL
flattens nested associative AND groups in CHECK expressions on restore; the two
reparsed schema dumps must match exactly. Existing
cluster roles are retained in this exercise; cross-cluster roles/secrets and
Supabase-managed service recovery are separate unverified dependencies.

The object test independently restores three synthetic byte streams and skips
a fourth receipt under a tombstone. SHA-256 verifies restored bytes. This is a
local filesystem recovery primitive, **not** a Supabase Storage backup or
provider recovery test. Database metadata cannot establish actual object bytes.
No real PDF, receipt, course video, student data, provider credentials or
production backup is accessed.

## Evidence and limitations (2026-10-13)

- Five safeguards passed: hosted libpq configuration removed; unrelated ports
  rejected; path traversal/unknown objects rejected; tombstoned receipt remains
  absent and restored bytes match; existing object directories refused unchanged.
- Native PostgreSQL 17 exercise PASSED: all 30 migrations replayed, 85 financial
  fixture assertions passed plus the progress DO-block suite; all 38 table row
  fingerprints/counts matched after real `pg_dump`/`pg_restore`; normalized
  schema/grants/RLS matched exactly; restored profile isolation suite passed.
- Restored synthetic rows included 9 profiles, 4 courses, 8 orders, 5 payment
  attempts, 3 payment events, 5 settlements, 5 enrollments, 4 grant sources,
  3 progress rows and 10 audit rows. Native dump measured 1.047 seconds;
  restore measured 2.734 seconds. Source-to-backup data loss observed: zero
  within the quiescent fixture; this does not measure production RPO.
- Separately restored 3 local synthetic object byte streams with matching
  SHA-256 digests; one tombstoned receipt was intentionally not restored.
- Docker CLI/engine is unavailable in this environment. Full Supabase Auth,
  Storage API access/recovery, signed delivery and provider reconciliation remain
  BLOCKED; no production recovery readiness claimed.
- Measure production RPO from recoverable backup/event timestamps, not local
  dump duration. Local restore timing excludes service redeployment, object
  transfer, deletion-ledger replay against real records, payment-provider
  reconciliation, monitoring and incident authorization.
- Missing production deletion ledger, operational encryption/key restoration,
  backup retention and separately replicated object design remain launch gates.
- Production-scale volume and actual managed service/object recovery must be
  verified before accepting AC-22. No DONE checkbox or master TASKS.md change is made.
