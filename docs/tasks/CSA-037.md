## Implemented behavior

Dependabot checks root Pub, npm and GitHub Actions dependencies weekly on Mondays
at 09:00, 09:30 and 10:00 Asia/Colombo, respectively. Each ecosystem allows at most
three open version-update PRs; GitHub's separate security-update limit is not
controlled by that value. Updates target `dev` and require normal review and CI.

Riverpod runtime, annotations and generators form one group across version types
because their compatibility is coupled. Other Pub, npm and Actions minor/patch
updates are grouped by ecosystem to reduce noise. Other major updates remain
individual PRs for migration review. No ignore rules suppress major or security
updates. No auto-merge workflow, credentials, private registry or external code
execution option is introduced.

The npm manifest pins `supabase` exactly. Review its `package.json` and regenerated
`package-lock.json` together: the CLI's optional `@supabase/cli-*` platform packages
must resolve to the version requested by the updated CLI package. Do not promote
those transitives to independent direct dependencies. Run `npm ci` and tooling
tests on the resulting PR, plus hosted Supabase checks for CLI changes.

For Flutter, review `pubspec.yaml` and `pubspec.lock` together and run the formatting,
analysis, tests and web-build gates. Flutter SDK constraints and CI SDK pins require
a coordinated SDK change when a package needs a newer SDK; Dependabot Pub updates
do not replace that decision. Actions updates must retain reviewed commit pins and
least permissions; CI tests must run for Dependabot PRs without privileged secrets.
