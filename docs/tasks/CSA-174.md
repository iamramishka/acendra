The new suite uses nonempty synthetic fixtures for all five audit ledgers and
actually attempts UPDATE, DELETE and TRUNCATE as the database operator. It also
checks RLS and absence of SELECT, INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES
and TRIGGER privileges for anon/authenticated/service_role. Generic financial
audit mutation raises 23514; the other ledgers raise 42501. Service privilege
checks matter because BYPASSRLS alone does not permit table access.

Audit metadata is confined by trusted writers: identifiers, command scope,
publication transitions, verified provider/bank references and safe entitlement
results. The new test rejects email/password/token/receipt-path/bank-account keys
in the exercised entitlement result. Reasons and course titles are user supplied;
they should not contain personal financial evidence. This is an operation-specific
review, not a universal DLP guarantee. Raw receipt bytes, credentials and tokens
are not copied into these audit writers.
