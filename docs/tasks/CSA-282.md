## Implementation and comparison

| Recorded artifact element | Implemented behavior and verification |
| --- | --- |
| My Courses back action | Explicit content action targets the existing dashboard/courses route in ready, loading, error and empty states; shared shell remains unchanged. |
| Course artwork/title and module/lesson counts | Feature-local, session-aware metadata provider reuses the existing active-enrollment read. It selects the exact course and uses the existing artwork widget; missing art keeps the approved placeholder. Singular/plural count copy is correct. |
| Your Learning Progress | Existing counts and percentage still derive only from saved records for current curriculum lessons. Loading/errors never become fabricated zero. Reload rereads the repository. |
| Continue learning / Start / Resume | Recent unfinished saved lesson activity selects its exact lesson; existing after-last-completed fallback remains when that signal is absent. Saved PDF/video activity counts as started even at zero completion. |
| Curriculum markers and durations | Completed, actual In Progress and unopened Up next remain distinct. Known duration/type labels wrap below titles, avoiding a wide trailing column. The next module expands by default. |
| Failure recovery | Progress and course metadata have independent explicit retries. Metadata failure does not erase usable progress; private error text is never rendered. Signed-out and obsolete account requests cannot replace current data or start a late progress read. |

The new metadata provider uses the existing library read (one active-enrollment
request per overview metadata load), avoiding an invented backend endpoint. Large
library query optimization is a future concern under that existing contract.
Overview rendering fetches neither protected lesson bodies nor saves progress;
course access remains backend-authoritative. No RPC, schema, grants or release
configuration was changed.
