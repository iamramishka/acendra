`bank-transfer-read` retains its existing authenticated owner/session verification and its request shapes. The owner-status response adds:

| Field | Source and representation |
|---|---|
| `amount_minor` | Immutable `orders.amount_minor`, decimal string preserving every bigint digit |
| `currency` | Immutable `orders.currency_code` |
| `order_created_at` | `orders.created_at`, timestamp distinct from receipt submission |

Migration `20261026000100_csa278_bank_order_metadata.sql` extends the owner branch of `csa179_read_bank_transfer`; its finance queue, MFA checks, private fields, grants, search path and mutations remain unchanged. Anonymous/authenticated roles still cannot execute privileged actor-parameter RPCs directly. No enrollment is created by a read.

The client parses decimal strings with BigInt and formats minor units without floating-point conversion. Old responses may omit the additive fields and show Unavailable; neither a zero amount nor a receipt timestamp is substituted. Malformed/mismatched records fail with safe error text.

The screen displays a clock/status card, exact amount, Ordered date, retained Submitted On date, existing four-step timeline and Orders/Explore exits. Rejected receipts retain their reason and resubmission action. A missing receipt goes to the unified instructions/upload screen. Refresh invalidates the current session's status read. Approved D-6 review-time copy is retained; no unsupported email promise is added.
