## Available operation matrix

Guest/student cannot invoke any of these 13 service-only RPC signatures directly.
A service credential is a trusted gateway, not an authorization substitute:
SQL independently verifies current account/session/roles. MFA means verified
claim AAL2 and matching current session AAL2; foreign/expired/deleted sessions
and revoked roles do not authorize work. Public role metadata is untrusted.

## Direct database, storage and unavailable planned operations

Public catalog RLS permits published metadata only. There is no browser admin
write grant on courses, course_sections, lessons, categories, course_staff,
roles or user_roles. Browser profile/order/enrollment/progress access remains
own-user or published-resource access, not unrestricted staff access.
Private receipts/course PDFs have restrictive direct storage denial even when a
permissive policy is added. Receipt/derivative paths and notes are not public
admin APIs. Storage service operations are trusted backend responsibilities.
The controlled csa061_bootstrap_super_admin operator procedure is unavailable
to service_role/anon/authenticated; public signup cannot bootstrap authority.

No privileged API currently implements existing-course editing, price changes,
curriculum editing, staff assignment, foreign student search/profile management,
bank destination activation, audit-history browsing, account restriction or
refund/reversal execution. Their browser controls must remain unavailable;
this verification does not imply these planned functions exist. Future APIs
must preserve the approved role matrix, reasons/audit and bank-change human
review. Audit rewrite/delete is prohibited for every application role.
