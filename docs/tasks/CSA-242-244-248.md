## CSA-242 — isolated CI test environments

`.github/workflows/supabase-foundations.yml` runs on a fresh GitHub-hosted
`ubuntu-24.04` job runner with `contents: read`, branch-scoped concurrency and
no project credentials. It exercises the disposable local test stack, runs
database tests and lint, starts a separate development stack for smoke checks,
and stops both task-owned stacks in `always()` cleanup steps. The wrapper only
accepts a local Docker endpoint and strips inherited `SUPABASE_*` variables.

## CSA-248 — isolated backend test data

`tool/local_supabase.mjs` derives project IDs and build snapshots from the
absolute worktree path and profile. Development and test use distinct project
IDs, data volumes, loopback-only Docker networks, generated configuration and
20-port blocks. CI runs on a fresh hosted runner and uses a fixed port base only
within that job. Tests run against the disposable `test` profile, which is reset
before execution; CI cleanup stops both profiles. The seed contains no user or
financial fixtures. Seven database test files each have one explicit `BEGIN`
and `ROLLBACK`, and use synthetic task-scoped identities/data. This avoids
shared persistent fixtures across local runs and CI jobs.
