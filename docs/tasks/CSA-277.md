## 2026-10-26 review correction — external browser entry

The full-page PayHere return was not covered by in-app `router.go` tests. The
application uses Flutter's default HashUrlStrategy, which reads an empty fragment
as `/`; configured `/payments/return?order_id=...` and `/payments/cancel?order_id=...`
therefore lost their intended route on a real page load. This is a blocking review
finding and supersedes the earlier automated no-blocking-finding review.

Temporary additional ownership was recorded in issue #221 for `lib/app/bootstrap.dart`,
new checkout presentation entry helpers and matching tests. No open PR #201/#202
changes these paths. The dedicated worktree is
`C:/Users/ramis/.codex/worktrees/payment-return-bridge/acendra`, branch
`fix/csa-277-return-bridge-review`; it updates this PR's existing implementation
branch with an additive commit. No original implementation worktree is edited.

Before restoring Supabase or creating the app, bootstrap redirects only those two
exact external paths to the same origin's hash route, carrying only the order
locator. It leaves existing route/auth fragments untouched, drops unrelated status
and destination hints, and cannot redirect to another origin. Native builds use a
no-op adapter. The provider's HTTPS/no-fragment URL validation, return configuration,
notification endpoint, settlement and entitlement authority remain unchanged.

The new pure entry regressions failed before the helper existed; all 30 focused
entry/status tests pass after implementation. Two regressions using the actual
SDK HashUrlStrategy are registered in the existing Chrome CI entry point, proving
that the unadapted URL reads as `/` and the adapted URL retains its order locator.
Final analyzer, release build, full-page browser check and current-head hosted CI
are required before this correction is considered verified. No merge, hosted
backend change or payment attempt is implied.
