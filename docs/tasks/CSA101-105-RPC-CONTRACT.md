# CSA-101–105 trusted RPC contract

Owner CODEX financial_finalization; issue #76; 2026-10-11. Root and both Edge workers agreed exact interfaces before implementation. New migration016 sole schema owner. All operations are service-role EXECUTE only, empty search_path, no direct ledger grants. Edge must authenticate current session for initialization and independently retrieve verified success for fulfillment. Provider acceptance remains unavailable; checkout stays disabled.

`csa101_initialize_checkout(p_actor uuid,p_session_id uuid,p_aal text,p_key text,p_order uuid,p_merchant text,p_environment text)` returns `{replayed,order_id,attempt:{attemptId,orderId,method,provider,merchantId,environment,currency,amountMinor,title}}`. `order_id` is internal order UUID; `orderId` equals attempt UUID string used as PayHere provider order reference; exact minor amount is a decimal string. Current account/session, owned payable online order and scope are checked. Actor/key replay rejects changed order/scope. Different keys reuse one initialized/pending attempt; scope change rejects. Customer contact stays Edge-only and cannot set price or financial identity.

`csa102_lookup_payment_attempt(p_provider_order_id text)` returns stored adapter `attempt` shape above directly, or null. Provider reference has unique index; only online PayHere bound scope is returned. Handler compares merchant/environment with trusted configuration.

`csa104_finalize_payment(p_attempt_id uuid,p_merchant text,p_environment text,p_event_id text,p_payload_hash text,p_external_settlement_id text,p_amount_minor bigint,p_currency text,p_confirmed_at timestamptz,p_evidence_reference text)` returns `{outcome,order_id,event_id}`; outcome processed/duplicate/reconciliation_required. Handler must verify callback checksum AND authenticated retrieval binding and RECEIVED status before calling. Event ID `payhere:received:<retrieved payment ID>`; evidence `payhere:authenticated_retrieval:<retrieved payment ID>`; lowercase SHA256 canonical JSON array `[provider,merchantId,environment,attemptId,orderId,paymentId,amountMinor,currency,"RECEIVED"]`. Observation timestamps/raw body excluded from replay hash. Confirmed time is trusted retrieval observation time, never client clock.

Lock order: initialization current account/session SHARE, principal/key advisory, order UPDATE, attempt UPDATE; fulfillment scoped verified settlement identity advisory, order UPDATE, attempt UPDATE, user/course advisory, enrollment UPDATE. Future bank/reversal/grant operations must retain order before beneficiary/course lock. Settlement uniqueness globally prevents rebinding a real payment to another order. Invalid mismatch reserves nothing. Exact duplicate is no-op; changed event binding/hash rejects. Extra real payments or late success for non-payable orders preserve immutable settlement/event/audit as reconciliation, no source revival.

Success atomically commits settlement, processed event, paid order/attempt, lifetime source grant/current enrollment, append-only audit and notification outbox. A revoked projection is preserved conservatively because its restriction scope is not yet modeled; new funded source history remains recorded and future restriction-aware CSA116/117 workflow must reconcile it. No email is sent in the transaction. CSA119 delivery and CSA116 general grant API remain separate.

Errors: 22023 invalid/mismatch/replay conflict, 42501 account/session/ownership denial, P0002 unavailable attempt, 55000 non-payable order, 23505 settlement already bound. Nothing in this contract approves production configuration, actual provider acceptance or deployment.
